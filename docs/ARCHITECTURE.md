# Architecture

The repository is a Vite/React TypeScript frontend and a Django REST Framework backend. Browser requests use the API base URL in `frontend/.env`; provider credentials remain in backend environment variables. SQLite is configured for local development. Backend API URLs are grouped under `api/` and version-independent errors use a shared DRF exception handler. Health reporting is served from the trips app and validated through a serializer. JSON logs carry timestamps, severity, logger names, and event metadata.

Routing and geocoding are isolated behind the `RoutingProvider` abstraction in `apps/routing/services`. `OpenRouteServiceProvider` calls the hosted Directions API with the `driving-hgv` profile and the Pelias search endpoint for geocoding. Route responses are validated, converted to normalized route objects, and deduplicated by geometry; no alternatives are fabricated. Location suggestions are cached for one hour. Since ORS's hosted alternatives endpoint has a documented 100 km calculation limit, a matching provider rejection retries the directions request without alternatives and returns the real primary route.

Checkpoint generation is implemented in `apps/routing/services/checkpoint_generator.py` and consumes the normalized route geometry, provider route distance/duration, timezone-aware departure datetime, and a 10/25/50-mile interval. It accumulates great-circle distances along consecutive route vertices, interpolates each checkpoint on the polyline (including antimeridian-safe spherical interpolation), includes both endpoints without duplicating an exact interval endpoint, and computes each ETA from the route-distance fraction. Geometry distance is proportionally aligned to the routing provider's reported total so displayed distances and ETAs agree with the provider summary. Checkpoint weather is attached by the weather service during trip analysis.

Weather retrieval is isolated behind `WeatherProvider`; `OpenMeteoProvider` requests the hourly `wind_speed_10m`, `precipitation`, and `snowfall` variables. It batches up to 50 distinct checkpoint locations per request, asks for mph and inches, uses UTC Unix timestamps to avoid local DST offsets, and caches normalized hourly responses for 30 minutes. Checkpoint matching selects the nearest hourly forecast within 30 minutes (ties select the earlier hour). Coverage outside the forecast horizon or missing individual measurements remains explicitly unavailable/incomplete; it is never defaulted to zero. Open-Meteo currently supports forecast horizons up to 16 days for the general forecast API ([official API documentation](https://open-meteo.com/en/docs)).

Risk calculations are isolated into checkpoint classification (`risk_calculator.py`), load-specific wind adjustments (`load_rules.py`), distance-weighted route exposure (`risk_miles.py`), and lexicographic route selection (`route_recommender.py`). Missing observations are represented as unavailable-weather miles, not Low risk. Recommendation results include comparison metrics, No Travel warnings, and an explicit incomplete-coverage status where applicable.

`POST /api/trips/analyze/` composes these services for each real route returned by the routing provider. It generates route-distance checkpoints and ETAs, attaches Open-Meteo's closest hourly row, calculates risk and risk miles, and returns the provider route geometry with the recommendation. The React API client only serializes trip inputs and renders the returned analysis; it performs no routing, weather, or risk substitutions. TanStack Query handles debounced location lookup and caching. Leaflet renders provider geometry, checkpoint popups, selected-route comparison, and checkpoint risk circles. The 0–48 hour control filters checkpoint layers by elapsed hours after departure; it does not request new weather observations while moving the slider.

For deployment, Django reads secrets, allowed hosts, CORS/CSRF origins, PostgreSQL credentials, and TLS-related settings from environment variables. Debug mode may use SQLite locally; production mode fails closed unless a non-placeholder secret, explicit host/CORS values, and a PostgreSQL database are supplied. Gunicorn serves the WSGI API. The Vite frontend is built to static assets with its public API base URL set at build time. Frontend assets and the API can be hosted independently; configure CORS to the exact HTTPS frontend origin.
