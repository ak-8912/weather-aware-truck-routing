# Architecture

The repository is a Vite/React TypeScript frontend and a Django REST Framework backend. Browser requests use the API base URL in `frontend/.env`; provider credentials remain in backend environment variables. SQLite is configured for local development. Backend API URLs are grouped under `api/` and version-independent errors use a shared DRF exception handler. Health reporting is served from the trips app and validated through a serializer. JSON logs carry timestamps, severity, logger names, and event metadata.

Routing and geocoding are isolated behind the `RoutingProvider` abstraction in `apps/routing/services`. `OpenRouteServiceProvider` calls the hosted Directions API with the `driving-hgv` profile and the Pelias search endpoint for geocoding. Route responses are validated, converted to normalized route objects, and deduplicated by geometry; no alternatives are fabricated. Location suggestions are cached for one hour. Since ORS's hosted alternatives endpoint has a documented 100 km calculation limit, a matching provider rejection retries the directions request without alternatives and returns the real primary route.

Checkpoint generation is implemented in `apps/routing/services/checkpoint_generator.py` and consumes the normalized route geometry, provider route distance/duration, timezone-aware departure datetime, and a 10/25/50-mile interval. It accumulates great-circle distances along consecutive route vertices, interpolates each checkpoint on the polyline (including antimeridian-safe spherical interpolation), includes both endpoints without duplicating an exact interval endpoint, and computes each ETA from the route-distance fraction. Geometry distance is proportionally aligned to the routing provider's reported total so displayed distances and ETAs agree with the provider summary. Weather fields are added by the next analysis phases.
